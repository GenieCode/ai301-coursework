# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Issue-specific claim | Read the claim comment against the issue context, especially the reported trigger and behavior. | Pass when the claim identifies the issue-specific behavior or trigger being investigated, states the next investigation action, and promises a later reproduction report. A claim-only draft does not need to assert a reproduction result. | required |
| Environment fit | Read the repro report's environment record against the issue context and repo-facts block. Check the repository revision, relevant runtime or dependency versions, operating-system or platform information when behavior can depend on it, and configuration needed to reach the reported path. | Pass when the recorded environment identifies the variables needed to recreate the relevant execution context. If it differs from the issue's stated target, the difference must be identified rather than silently treated as equivalent. Do not require facts that cannot affect the reported behavior. | required |
| Followable path | Read the setup and reproduction actions in the repro report against prerequisites in the issue context and repository documentation. | Pass when a stranger can move from the stated starting state to the tested trigger using the supplied commands, inputs, routes, and actions without inventing a material missing step. Equivalent commands are acceptable when they produce the same tested state. | required |
| Target behavior evidenced | Read the report's observed result and its output excerpts, logs, screenshots, or other artifacts against the behavior and trigger described by the issue. | Pass when the evidence shows what happened at the issue's relevant trigger and is capable of distinguishing the reported behavior from an adjacent problem. For a cannot-reproduce result, pass when the evidence shows the tested trigger and the different behavior that occurred. Confidence without supporting observation fails. | required |
| Honest conclusion | Compare the report's stated result, expected behavior, observed behavior, and artifacts. | Pass when the conclusion does not claim more than the recorded observation supports. A reproduced, partially reproduced, or cannot-reproduce conclusion may pass when it accurately describes the evidence and material uncertainty or environment differences are disclosed. | required |
| Repository conventions | Read the claim and repro comments against the repo-facts block, issue-thread instructions, contribution documentation, and any required comment template or disclosure policy. | Pass when the comments satisfy every applicable repository requirement. If the repository requires disclosure of AI assistance, the posted text must contain that disclosure. The claim must not promise a fix or deadline, and neither comment may substitute another person's result for the author's own work. | required |

## Verdict rule

Accept only when every applicable required check passes. Reject when any applicable required check fails or is unclear. During live grading of a claim-only draft, checks that require a completed reproduction report are not yet applicable and do not cause rejection; the issue-specific claim and applicable repository-convention requirements must still pass. Preferred checks, if later added, never change the verdict.
